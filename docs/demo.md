# Delim — сценарий демо (5–7 минут)

Основной путь — через реальный MAX-клиент. Fallback (ниже) — локальная демо-группа
через devseed, если OCR/MAX временно недоступны. Никаких фейковых «production»
состояний: показываем реальные экраны и реальные операции.

## Подготовка (один раз перед демо)

```bash
cp .env.example .env                # при необходимости заполнить dev-секреты
make dev-up                          # сборка и подъём полного стека
make demo-seed                       # локальная демо-группа с участниками и расходами
# для реального MAX: настроить MAX_* и:
make max-setup && make max-check
```

Открыть мини-апп: внутри MAX (webview) либо локально `make web-dev`
(`http://localhost:5173`, dev-сессия из `.env.local`, созданной demo-seed).

## Главный demo при наличии MAX

Полный MAX-first сценарий (реальные чат и мини-апп):

1. **MAX group chat** — открыть групповой чат с ботом Делим.
2. **/new** — в чате нажать/ввести `/new` → бот присылает кнопку «Открыть форму расхода».
3. **Mini App** — по кнопке открывается мини-апп сразу на форме нового расхода (launch action `new_expense`).
4. **Expense** — заполнить и сохранить расход, подтвердить.
5. **Bot notification** — в чат приходит «Расход подтверждён: «…» — …» с кнопкой «Посмотреть» (launch `expense`).
6. **/balance** — бот отвечает «Тебе должны / Ты должен …» с кнопкой «Открыть баланс».
7. **Settlement callback** — участник отмечает погашение → уведомление с кнопкой «Подтвердить» (подписанный callback) → подтверждение вторым пользователем прямо из чата.
8. **Receipt OCR** — загрузка чека через мини-апп, распознавание, ручная правка.
9. **Export** — выгрузка CSV/PDF/XLSX.

Дополнительно: владелец привязывает чат к группе и синхронизирует участников
(секция «MAX-чат» на дашборде группы).

## Основной сценарий (fallback)

1. **Открыть Delim.** Показать список групп (`Ваши группы`).
2. **Создать/открыть поездку.** «Создать группу» → название «Поездка в Сочи» →
   экран группы.
3. **Участники.** «Участники» → показать владельца и добавленных; при желании
   сменить роль (admin/member).
4. **Загрузить чек.** Панель «Добавить чек» → выбрать фото чека → «Распознать чек».
5. **OCR.** Показать статус распознавания (queued → processing → «Проверьте чек»).
6. **Ручная правка.** Поправить позиции/итог/дату в OCR-review; удалить лишние
   строки; отметить участников по позициям.
7. **Split.** Продолжить к расходу, выбрать режим деления (равный/доли/%/фикс/по
   позициям), проверить «Осталось/Всего».
8. **Confirm.** «Сохранить расход» → «Подтвердить» (расход создаётся в Core
   только здесь — граница подтверждения OCR).
9. **Balance.** «Баланс» → «Тебе должны / Ты должен», разбивка по участникам.
10. **Settlement.** «Погашения» → «Отметить погашение» → подтвердить вторым
    участником → баланс сходится.
11. **Export.** Выбрать формат (CSV/PDF/XLSX) → «Подготовить файл» → «Скачать».

## Фолбэк (OCR/MAX недоступны)

Использовать заранее подготовленную локальную группу из `make demo-seed`
(подтверждённые расходы + расход на проверке):

- шаг 4–8 заменить на редактирование/подтверждение уже загруженного демо-расхода
  и создание расхода вручную («Добавить расход» в группе);
- шаги 9–11 (balance → settlement → export) выполняются как в основном сценарии;
- показать, что при недоступном Document мини-апп корректно сообщает
  «Сервис временно недоступен», а финансовые операции работают (Core жив).

Если нет реального MAX-клиента: демо через `make web-dev` с dev-сессией demo-seed.

## Быстрая самопроверка перед выходом

```bash
make audit           # сборка/тесты/typecheck/compose конфиг
make smoke           # интеграция: expense → settlement → adjustment → receipt → export
make document-ocr-check   # OCR-pipeline на фикстурах (нужно окружение Document)
```
